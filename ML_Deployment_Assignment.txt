TASK 1: Difference Between Training and Deployment of an ML Model
--------------------------------------------------------------------------------
Training is the offline process where a machine learning algorithm learns patterns, weights, and relationships from historical datasets. In contrast, deployment is the process of taking the trained model and integrating it into a live production environment (e.g., behind a cloud API) so it can process real-world data and serve predictions to live users. For example, in Zomato's food recommendation system, training happens offline on cloud servers where historical order histories, cuisine ratings, and delivery patterns are processed to build a predictive recommendation model. Deployment occurs when this trained model is hosted on production servers; whenever a user opens the Zomato app, the deployed model takes the user's current location and preferences to instantly generate and serve a personalized list of top restaurant recommendations.

TASK 3: Online vs. Offline Deployment Choice for a BookMyShow-like App
--------------------------------------------------------------------------------
I would choose offline (batch) deployment combined with caching for a movie recommendation feature in a BookMyShow-like app. User movie preferences and general movie catalogs do not change second-by-second, so pre-computing recommendations offline (e.g., every few hours or nightly) and storing them in a fast database like Redis allows serving recommendations with near-zero latency to millions of concurrent users. Retraining deep recommendation models on massive user booking logs is computationally expensive and is best scheduled periodically offline rather than run in real-time. This batch deployment approach ensures low infrastructure costs and high system throughput while keeping recommendations sufficiently fresh whenever users open the app.

TASK 5: Deployment Challenge in a Flipkart-like E-commerce App
--------------------------------------------------------------------------------
- Challenge: Prediction Latency Spikes and Server Overload During Peak Traffic Events (e.g., Big Billion Days Sale)
  Description: During mega sale events, traffic surges dramatically with tens of thousands of concurrent user queries per second for personalized product recommendations and search re-ranking. Running real-time inference on complex deep learning models for every user request can overload servers, causing high response latency or API timeouts and leading to cart abandonment.

- Suggested Solution: Optimized Model Serving & Multilevel Caching
  Optimize inference models using runtime toolkits like ONNX Runtime or TensorRT to reduce prediction latency, combined with caching popular recommendations in Redis for high-frequency queries. Additionally, hosting the inference service on a microservices cluster with Horizontal Pod Autoscaling (HPA) ensures prediction server instances automatically scale up based on CPU/GPU demand during traffic spikes.

TASK 5: FastAPI vs. Flask Comparison for IPL Fantasy Points Prediction API
--------------------------------------------------------------------------------
To build an IPL fantasy points prediction API, I would choose FastAPI over Flask. An IPL fantasy league application experiences massive spikes in concurrent traffic during live matches, where thousands of users continuously request real-time score and fantasy point predictions. FastAPI is natively built on asynchronous Python (ASGI via Starlette and asyncio), enabling significantly higher request throughput and microsecond latency compared to Flask's traditional synchronous WSGI model. Furthermore, FastAPI's built-in Pydantic integration automatically validates complex player statistics payloads, and its automatically generated interactive Swagger/OpenAPI documentation (/docs) makes frontend and mobile application integration fast, reliable, and developer-friendly.

TASK 1: Model Training & Saving (train_sentiment_model.py -> review_sentiment_model.pkl)
--------------------------------------------------------------------------------
Python Training Code (train_sentiment_model.py):
import pickle
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

reviews = [
    "Great product, excellent quality and fast delivery!",
    "Worst item ever, poor build quality and damaged piece.",
    "Very good performance, highly recommended purchase!",
    "Horrible experience, stopped working within two days.",
    "Value for money, works nicely and looks awesome.",
    "Cheap quality material, totally useless and bad experience.",
    "Superb battery life, crisp display and awesome camera!",
    "Extremely disappointed with this purchase, complete waste of money."
]
labels = [1, 0, 1, 0, 1, 0, 1, 0]

pipeline = Pipeline([
    ('tfidf', TfidfVectorizer(ngram_range=(1, 2))),
    ('clf', LogisticRegression())
])
pipeline.fit(reviews, labels)

with open('review_sentiment_model.pkl', 'wb') as f:
    pickle.dump(pipeline, f)

Result: Saved trained model to file 'review_sentiment_model.pkl'.


--------------------------------------------------------------------------------
TASK 2: Flask Prediction API (predict_review.py)
--------------------------------------------------------------------------------
Flask API Code (predict_review.py):
import os
import pickle
from flask import Flask, request, jsonify, render_template
from flask_cors import CORS

app = Flask(__name__, template_folder='templates')
CORS(app)

MODEL_FILE = 'review_sentiment_model.pkl'

@app.route('/predict', methods=['POST'])
def predict_sentiment():
    data = request.get_json() # Reads JSON input
    review_text = str(data['review']).strip()
    
    with open(MODEL_FILE, 'rb') as f:
        sentiment_pipeline = pickle.load(f)
        
    pred = sentiment_pipeline.predict([review_text])[0]
    sentiment_label = "Positive" if pred == 1 else "Negative"
    
    return jsonify({
        "status": "success",
        "review": review_text,
        "sentiment": sentiment_label
    }), 200

--------------------------------------------------------------------------------
TASK 5: Project Workflow Explanation (5-7 Sentences)
--------------------------------------------------------------------------------
The End-to-End Sentiment Analysis Web Application follows a client-server architecture where user input flows seamlessly from the browser to the backend machine learning model. First, the user enters a product review into the text box on the review_predictor.html web frontend and clicks the 'Predict' button. The frontend JavaScript captures this text input and sends an asynchronous HTTP POST request formatted as a JSON payload to the Flask backend endpoint /predict using the browser's fetch() API. Upon receiving the payload, the Flask API extracts the review text using request.get_json() and feeds it into the pre-trained review_sentiment_model.pkl scikit-learn pipeline, which vectorizes the text and predicts whether the sentiment is 'Positive' or 'Negative'. Flask then constructs a structured JSON response containing the predicted sentiment and returns it to the client with an HTTP 200 OK status code. Finally, the JavaScript callback receives the JSON response, dynamically manipulates the HTML DOM, and displays the sentiment badge to the user in real time without refreshing the webpage.
